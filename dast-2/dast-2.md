## Часть 2. Добавление входного корпуса и словаря
Важным элементом фаззинг-тестирования является правильная подготовка входного корпуса и словаря, на основе которого будет происходить генерация новых тест-кейсов.

Для знакомства с процессом подготовки входного корпуса для фаззинга предлагается запустить фаззинг-тестирование с помощью AFLplusplus для одной из двух утилит командной строки:
- Вариант 1. [xmlstarlet](https://sourceforge.net/p/xmlstar/code/ci/master/tree/) - утилита для работы с XML.
- Вариант 2. [jq](https://github.com/jqlang/jq) - утилита для работы с JSON.

Результат сдаётся по [общим правилам](../SUBMISSION.md). В PR должны находиться:

- `submission/submission.json` с вариантом, версией проекта, окружением и командами;
- `submission/artifacts/input/` с начальным корпусом из как минимум 3 подготовленных входных файлов;
- `submission/artifacts/dictionary.dict` с подготовленным словарём;
- `submission/artifacts/out/` с полными результатами собственного запуска AFLplusplus;
- журнал `submission/artifacts/logs/build.txt`;
- скриншоты `submission/artifacts/screenshots/build.png` и `submission/artifacts/screenshots/fuzzing.png`.

### Сборка с инструментацией

Подготовьте окружение и соберите актуальную в апстриме версию выбранной утилиты
с инструментацией AFLplusplus, как в [части 1](../dast-1/dast-1.md).
Сохраните журнал конфигурирования и сборки в `submission/artifacts/logs/build.txt`.

Сделайте `submission/artifacts/screenshots/build.png`: в кадре должны быть
видны команда сборки с инструментацией и её успешное завершение.

### Подготовка входного корпуса и словаря

Создайте каталог `input/` и подготовьте в нём как минимум 3 различных корректных
файла выбранного формата: XML для `xmlstarlet` или JSON для `jq`.
Примеры должны использовать разные конструкции формата. Проверьте, что
выбранная команда исследуемой утилиты обрабатывает каждый файл корпуса.

Подготовьте файл `dictionary.dict` в формате словаря AFLplusplus.
Включите в словарь характерные элементы синтаксиса выбранного
формата, которые фаззер сможет использовать при генерации новых входных данных.

### Запуск фаззинг-тестирования

Запустите собранную утилиту под AFLplusplus с подготовленным корпусом и словарём
(опция `-x`)

Сделайте `submission/artifacts/screenshots/fuzzing.png`: в кадре должен быть
виден работающий AFLplusplus.

### Сдача задания

Аналогично части 1, дополнительно укажите поле `fuzzing.dictionary` со
значением `submission/artifacts/dictionary.dict`.

### Итог 2 части

В ходе 2 части мы научились готовить входной корпус и словарь и использовать
их при фаззинг-тестировании утилит командной строки.
